Accessibility

The service can be used without a mouse, with a screen reader and with any display settings

We built Attrfill so that product cards can be filled in and reviewed by people with different abilities: blind and low-vision people, people who find a mouse hard to use, and people who are sensitive to motion on screen.

Target: WCAG 2.1, level AA

WCAG is the international set of web accessibility guidelines; level AA is the one required of most government and large commercial services. We checked the interface against these guidelines ourselves; there has been no independent audit yet.

What is supported

Keyboard

  • Every action is available from the keyboard: Tab moves between elements, and the focus ring is always visible.
  • A "Skip to content" link at the top of every page skips the menu.
  • After a decision on a value, the focus moves to the next one by itself, so you do not have to look for it.
  • Any decision can be undone within 5 seconds: an accidental press will not spoil the data.

Screen readers (VoiceOver, NVDA, TalkBack)

  • All buttons have clear names, for example "Correct: Brand — Apple".
  • The result of each action is announced: “Brand — confirmed "Apple". Left to review: 1”.
  • Errors are announced at once and do not disappear by themselves until they are closed.
  • Charts and colored bars are duplicated with text and numbers.
  • A file page updates while it is processed without interrupting reading; updates can be paused.

Vision

  • Text contrast meets level AA in both the light and the dark theme.
  • The default theme is dark; light or "System" can be chosen with the "Theme" switch, and the choice is remembered.
  • The system "Increase contrast" mode and Windows high contrast are respected.
  • Meaning is never conveyed by color alone: every status has a label.
  • The page can be zoomed up to 400% and text spacing increased: nothing disappears or slides sideways.

Motion and devices

  • With the system "Reduce motion" setting animations are turned off, and with "Reduce transparency" blur is.
  • Phones and tablets from 320 px wide; buttons on touch screens are at least 44 px.
  • Input fields on a phone do not trigger automatic page zoom.
  • The result can be printed or saved as PDF, without menus and buttons.

Keyboard shortcuts

They work in the review queue, in the "Review the values of this file" section of a file page (everything there works as in the queue) and in the value tables on card and file pages when a value is selected (click a row or move to it with Tab). In the queue and in a file review the keys also work without a selection, on the top value on screen. While you type text, the keys stay out of the way.

KeyAction
1Correct: confirm the value
2Fix: open a field for the right value
3No value: the card really does not have it
4 5Choose the first or second other possible answer
↑ ↓Previous or next value
TIn the review queue and in a file review: show or hide the full card text; the place the disputed value was taken from is highlighted
F, Ctrl/⌘ + FFind a word in this card's text only (Ctrl/⌘ + F when the text is open; pressed again in the search field, it is the browser's usual page search). Enter: next match, Shift + Enter: previous, Esc: back to the value
ZUndo the last decision while the notice is on screen (5 seconds)
AIn the review queue and in a file review: the same decision for the same value on other cards with the same title, while the notice is on screen
EnterSave the typed correction
EscClose the correction field without saving
⌘/Ctrl + EnterSubmit the card for filling from any form field

In Safari on a Mac, to make Tab move through buttons too, press ⌥ + Tab or turn on "Press Tab to highlight each item on a webpage" in Safari settings.

Where it was tested

  • Chrome, Edge and Yandex Browser (Chromium engine): version 120 and newer.
  • Safari 18 (WebKit engine) on Mac; on iPhone and iPad, iOS 17.2 and newer.
  • Firefox 121 and newer.
  • Screen widths from 320 to 2560 px, regular and Retina displays.

Known limitations

  • A decision can be undone only within the first 5 seconds; after that it can be changed on the card page.
  • We checked screen reader support through the markup and the announced messages; a full walkthrough with VoiceOver on iPhone and with NVDA has not been done yet.
  • The downloadable CSV and JSON files are data, not documents: they have no descriptions for a screen reader.
  • Browsers older than those listed above show the "Outdated browser" page.

Found something that is inconvenient or impossible to use? Tell the project team what you were doing, in which browser and with which assistive software, and we will fix it first.
