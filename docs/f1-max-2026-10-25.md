## Data and evaluation boundaries

The original labeled pilot set contains 35,977 cards. The fields are seller-exported attributes, not new manual gold labeling. The labeling is partial and contains disputed spellings, ranges and errors. `GOLD=partial`: a missing label does not mean the attribute is absent. The primary Macro F1 is the mean over the 16 labeled attributes from the list for the corresponding category. Macro F1 over all known labels is also published: fields outside the category list count as misses. These are different metrics; denominators and rules were not changed.

1,997 test cards were reserved before the new tuning. Their bytes were not changed: SHA-256 `6528369df229ae379469052921f298c8496a6503aef8a6d87c81648338cc8d07`. Normalized identical texts, title families and model codes were grouped with heuristic keys. The initial heuristic over-merged entire brands via memory, SIM and watch sizes. This was found from the composition of the groups, without predictions on the test set. Only the development split was fixed; the original test cards were kept, and another 418 cards linked to them were excluded from training.

On the development side: 28,142 training cards and 5,420 validation cards. The final evaluation weights were retrained on their union, 33,562 cards; the context classifier uses 33,560 of them (two undetermined categories were skipped). The learned dictionaries, prior, reference and NER of the evaluation configuration were also trained only on these 33,562 cards. Full-size production weights from the previous version were not carried over into the independent measurement.

Key check: `python3 results/f1-max/audit_split.py`. Zero key overlap is a verifiable property of this heuristic; it does not prove the absence of every possible similarity. The data is historical, and part of the code was previously developed on this catalog. This is a local held-out test of the new tuning, not an external blind benchmark and not an official result.

## What was tested on validation

Compared: nearest neighbors k=1/3/7, TF-IDF with character/word features, SGD log-loss with alpha from 1e-6 to 1e-3, LinearSVC C=1/10/100, title-only variants and variants with 800 characters of description. The threshold was chosen from 0/0.15/0.3/0.45/0.6/0.75/0.9; replacing the general prior was tested separately. Features see only the input text; gold is stored separately and serves as target classes. At least eight labeled training examples per field/category. The vocabulary and IDF are built on training data only.

Parameters were selected using the original Ruby scorer: baseline Macro F1 0.6712, selected combination 0.7903. Full compression to 4,096 residual coefficients per class gave 0.7887 in the real Pipeline. Therefore exact weights were kept for fields where compression worsened the result; for the rest, the verified sparse weights were kept. Settings are recorded in `config/context-policy.json`.

RuBERT-tiny2 was retrained separately: 28,142 cards, 4 epochs, MPS, token-F1 of 0.920 on the internal split. This token-F1 is not attribute-extraction F1. On the shared validation, the Transformer with context scored 0.7824 versus 0.7884 for the original perceptron with the original context; the Transformer was rejected. Extending NER to Pattern fields also worsened the overall check and was rejected. The perceptron remains the production tagger.

The 0.6450 figure from the previous report refers to a different set of 2,168 cards and different training data. It must not be subtracted from the new evaluation F1 and presented as a comparable gain.

## Behavior of the new layer

`Extraction::Context` is a conditional prior: it predicts missing attributes from the text of products with similar features. It does not replace values already extracted; sometimes it replaces only the previous general statistical suggestion, if the field policy allows it. This layer does not predict brand or model. The accessory compatibility restriction remains in place.

Every such suggestion has `rule=context`, `source=prior`, `origin=unverified_identity` and always requires human review, including in standard mode. It is a guess, not a fact confirmed by the text. The confidence number is capped at 0.95 and estimated from the precision of the changed validation suggestions; this is not independent calibration and not a guarantee of correctness. The strict auto-acceptance policy and programmatic type checking remain in force. If there is no model, the file is corrupt, the category is unknown or there is not enough data, the previous Pipeline runs.

The external LLM was turned off in all measurements. Python and scikit-learn are needed for training; the application runs inference itself in Ruby, with no Python service. The delivery includes checks that the two implementations agree on classes and numeric scores.

## Two configurations

1. `results/f1-max/models/` — frozen evaluation weights that exclude the test set and the 418 linked cards. The final evaluation metrics apply only to them.
2. `config/` — the production delivery: the previous base, trained on the full catalog of 546,069 products, extended with the new context layer, retrained on all 35,975 cards of the ten defined pilot categories. The remaining two pilot cards are generic. This training already includes the test cards; there is no separate independent evaluation of this full delivery. The previous reference/NER/dictionaries/calibration of the full catalog are kept. Details of the previous training: `docs/full-catalog-training-2026-10-24.md`.

To disable the new layer for comparison: `CONTEXT=off`. The regular `bin/learn` trains the previous layers; the context is trained with separate commands from `script/context/` so that the training set boundaries are passed explicitly.

## Reproduction

```sh
bundle install
python3 results/f1-max/audit_split.py
LLM_MODE=off GOLD=partial bin/rails runner script/f1_replay.rb tmp/my-f1-replay
```

The last command runs baseline and candidate on the same evaluation weights/cards and saves predictions, reports and SHA-256 hashes. The output directory must be new. It also works in a ZIP without `.git`: the state of the sources is fixed by SHA-256 before and after the run. The Git-less archive was verified with a separate run.

Retrain the evaluation configuration (without changing the production `config/`):

```sh
gunzip -c results/f1-max/train.csv.gz > tmp/f1-train.csv
LLM_MODE=off GOLD=partial LEARN_WORKERS=3 bin/rails runner script/train_isolated.rb tmp/f1-train.csv tmp/f1-models
LLM_MODE=off GOLD=partial bin/rails runner script/context/export.rb tmp/f1-train.csv tmp/f1-fit.jsonl tmp/f1-models
uv run --with scikit-learn==1.9.1 --with numpy==2.2.5 --with scipy==1.18.0 python script/context/train.py tmp/f1-fit.jsonl tmp/f1-models/context.json.gz --policy config/context-policy.json --terms 4096
```

Training is deterministic via seeds, but bit-for-bit identical new weights across platforms/library versions are not guaranteed. The original weights are shipped for exact reproduction of inference. Hashes of inputs, model, trainer, policy and library versions are stored in artifacts/manifests. To re-verify numeric compatibility, use `script/context/parity.rb`.

The exact trainer source that produced the shipped weights is kept as `results/f1-max/trainer-used.py` (its SHA matches `metadata.trainer_sha256`). In the maintained `script/context/train.py`, class selection on exact margin ties was additionally fixed after training: the stable sort now matches Ruby. This does not change the trained coefficients or the production Ruby inference; a separate regression test checks both Python branches. The trainer hash is now taken before training.
